# 速習資料の型

## 構成

```
# <読み手の問いの形のタイトル>

> 想定読者 / 省いたもの / 所要時間 / 検証方法（1 行ずつ）

## 0. 一枚で          ← 問いに答える表。本文を読まなくても持ち帰れる
## 1..n 本文         ← 表の各行を 1 節ずつ展開する。1 節に例は 1 つ
## n+1 チェックリスト  ← 読み手が明日から使う形（レビュー項目など）
## n+2 理解度チェック  ← 3〜5 問。答えは <details>
## 付録：再現         ← コマンド 3 行と、ファイルの表
```

## 文体

- 1 段落は 1〜2 文にする。長い説明は段落を分ける。
- 主張の直後に例を置く。例の直後に、その例から読み取ることを 1 文で書く。
- 太字は 1 節に 1 つまで。その節の結論に使う。
- 用語は、初出で 1 回だけ定義する（「CTI（帰納法の反例）」）。
- 書き手が確信を持てないことは、本文から外すか「未検証」と書く。ぼかした言い方で残さない。
- ペルソナの言語で書く。ペルソナ本人の文体（段落の長さ・語彙）に寄せる。

## 引用のマーク

検証スクリプトは、次のマークの直後のコードブロックを実物と照合する。

````markdown
<!-- output: z3-is-odd -->
```
x % 2 === 1: sat
```

<!-- source: examples/z3/01-is-odd.mjs -->
```js
const s = new Solver();
```
````

- `output:` の後には `checks.json` の `name` を書く。ブロックの各行が、実行結果に順に現れなければならない。長い出力は途中の行を省いてよい。
- `source:` の後にはファイルパスを書く。ブロックがファイルの連続した一部と一致しなければならない。

## 理解度チェックの作り方

- 各問いは、本文の「一枚で」の表の 1 行に対応させる。
- 「〜は何か」ではなく、判定を問う（「この緑で安心できない理由は？」）。
- 答えは 2〜3 文。本文のどの例で確かめられるかを書く。
- 誤答しやすい選択肢（「unsat なら実装は正しい」）を問いの形にする。

## 冗長さの点検

書き終えたら、1 節ずつ次を確かめる。

1. ペルソナの「既に知っていること」に載っていることを説明していないか。載っていれば削る。
2. この節を消したら、理解度チェックのどれかが答えられなくなるか。ならないなら消す。
3. 例は、その節の主張に必要な最小の大きさか。
