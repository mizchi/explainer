この PR の、オンコールの SRE にとっての価値（下流のサービスが落ちたり遅くなったりしたとき、全クライアントが 100ms ごとに一斉に再試行して負荷をかけ続けることが減り、復旧しやすくなる／再試行の波がそろわなくなる、など障害時の振る舞いの変化）を、説明の最初の 2 段落（または最初の 2 つの節）のうちに述べていれば PASS。
「待ち時間を指数的に増やし、ランダムな揺らぎを足した」のような、コードの仕組みの言い換えだけでは価値に数えない。
仕組みの説明（指数バックオフ・ジッタ・計算式）から始め、障害時に何が変わるかが 3 段落目以降にしか出てこなければ FAIL。
