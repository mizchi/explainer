### 既知の省略では、また差が出なかった。理由は依頼文にある

- 既知を説明する見出しも、「〜とは」の定義し直しも、あり・なしとも 1 つもなかった。核心の説明も、あり・なしとも正しかった。
- 2 つの crash-course のケースは、どちらも依頼文に「説明は不要」と書いている。**依頼文で明示された既知は、スキルがなくても省かれる。**
- スキルのペルソナが効くはずなのは、既知が依頼文に書かれておらず、ペルソナのファイルや公開情報から読み取る必要があるときである。次のケースはそれを測る。
  - 依頼文には「`personas/<id>.md` の人向けに」とだけ書き、既知はペルソナのファイルにだけ書く。ファイルは `append_system_prompt` か依頼文への同梱で渡す（eval の作業ディレクトリは空で始まるため）。

## 2026-09-26（4 回目）：crash-course の skips-known を具体的にして再実行

3 回目は `skips-known` の判定が 2 対 1 に割れた。そこで、既知とする項目（K1〜K4）と、既知に含めない項目（浮動小数点の誤差、丸め方向・タイミング、安全な整数の範囲など）を grader に列挙した。「説明している」は、見出しを割くか 2 文以上とし、コード例の中での使用は数えない、と定義した。依頼文は変えていない。

### skips-known の新しい基準は、今度は全部を落とした

- 判定の割れは消えた。6 回とも 3 票すべて FAIL だった。
- しかし、6 つの資料を K1〜K4 の語で検索しても、本文で説明している箇所は見つからなかった。見つかったのは、コード例の中の型エイリアス（`type Yen = number` など）だけで、これは基準で数えないと定めたものだった。
- eval は判定モデルの票だけを保存し、理由は保存しない。どの K に当てはめたかは確かめられない。考えられる原因は 2 つ。
  - コード例の型エイリアスを K1 と読んだ
  - 「number は 64bit 浮動小数点」のような文を K2（number が 1 つの型であること）と読んだ
- どちらにしても、この grader は今、資料の違いを区別できていない。**`skips-known` は現状では信頼できない**。Δ への影響はない（あり・なしとも 0/3）。

次の手：
- 判定モデルを強くする（`--judge-model` で haiku 以外）。基準の読み違いが判定モデルの限界によるものかを切り分けられる。
- または、判定を機械的にする。資料の見出しに K1〜K4 の語が出るかを `regex` grader で見る。

### この環境の制約：シェルが動かなかった

実行したコンテナでは、eval のサンドボックス内の Bash が起動時に失敗しました（`apply-seccomp: write /proc/self/uid_map: Operation not permitted`）。
bubblewrap と socat は入れましたが、入れ子のコンテナでユーザー名前空間を作れませんでした。
eval はサンドボックスなしでシェルを動かすことを拒否します。それを回避する設定はしていません。

そのため、コードを実行したかどうかを見る grader は、この回の結果では意味を持ちません。
下の表は、それらを**除外して**計算し直した値です（重みは各 grader の `weight`）。

| 除外した grader | 理由 |
|---|---|
| `crash-course/ran-code`, `crash-course/outputs-shown` | Bash が失敗しても `tool_used` は呼び出しを数える。出力は実行されていない |
| `book/ran-answers`, `book/answers-checked` | 同上 |
| `first-reader-no-rewrite` の全体 | first-reader は Python のスクリプトを Bash で動かす。ケースごと無効 |

### 数値に出ない観察：実行できなかったことを報告したか

`crash-course` と `book` の 8 回は、どれも Bash が失敗していました（トレースに `uid_map` のエラーが 1〜5 件）。

- **あり：4 回中 4 回**が、最後の返答で「スクリプトを実行できず、検証できていない」と報告した。
- **なし：4 回中 0 回**。コードと出力を載せた資料を、そのまま完成品として渡した。

スキルの「検証できなかったことは『未検証』と明記する」が、そのまま効いています。
逆に言えば、スキルなしの資料に載っている出力は、実行されていないのに実行結果のように見えます。
